## 项目简介

moon-rulescope 是一个使用 MoonBit 编写的本地优先业务规则冲突检测与行为差异分析工具，主要解决“单条业务规则看起来合理，但多条规则组合后产生矛盾、遗漏或优先级覆盖”的问题。用户可以通过简洁的规则描述定义输入字段、输出字段、判断条件和规则优先级，系统会自动从字段范围和规则阈值中提取边界值，构造候选输入路径，检查同优先级冲突、不可达规则、优先级遮蔽、覆盖缺口、重复规则和版本行为变化，并生成可复现的最小反例和修复建议。

项目面向需要维护条件规则的开发者、产品经理和业务人员。典型场景包括电商优惠与订单审核、企业报销和审批流程、内容访问控制、保险受理、会员权益、资格判断和游戏活动配置等。相比只执行规则的普通规则引擎，moon-rulescope 更关注“这些规则组合起来是否仍然自洽”，可以在规则上线前发现隐藏冲突，并把抽象问题转换成具体输入案例，帮助团队快速复现和确认业务意图。

## 项目方向与适用场景

moon-rulescope 的方向是确定性、可解释、本地化的业务规则质量分析。项目不依赖在线模型或后端服务即可运行，核心分析结果由 MoonBit 程序确定性生成，适合在命令行、持续集成流程或浏览器工作台中使用，也方便后续接入自然语言规则录入、决策表和现有业务系统。

适用场景主要包括：

- 电商团队检查优惠叠加、订单审核、退款和会员权益规则是否冲突；
- 企业检查报销、请假、采购和权限审批规则是否存在遗漏或遮蔽；
- 内容平台检查年龄、地区、会员等级和内容分级规则是否自洽；
- 保险、教育和公共服务场景检查受理条件、资格判断和人工复核规则；
- 开发团队在规则修改后比较两个版本的实际行为变化，而不只查看文本差异；
- 个人或团队在不上传内部规则和业务数据的情况下完成本地分析。

## 拟实现的核心功能

moon-rulescope 当前实现和规划的核心功能包括：

- 支持整数、布尔值和枚举类型的输入字段与输出字段；
- 支持等于、不等于、小于、小于等于、大于和大于等于六种比较运算；
- 支持通过简洁 DSL 描述规则名称、条件、输出动作和数字优先级；
- 根据字段上下界、规则阈值及其相邻值自动生成边界候选输入；
- 检测同一输入下同优先级规则对同一输出给出不同结果的冲突；
- 检测条件无法满足的不可达规则，以及能够命中但始终无法决定输出的遮蔽规则；
- 检测输出未覆盖的输入路径、重复规则、重复条件和无效字段引用；
- 为每个冲突生成可复现的最小反例、命中规则链路和修复建议；
- 对两个规则版本执行相同候选输入，识别新增决策、删除决策、决策值变化和胜出规则变化；
- 提供 MoonBit 命令行工具，可直接运行电商、报销、内容访问和保险受理示例；
- 提供本地 Web 工作台，支持在线编辑规则、切换示例、查看覆盖率、检查决策轨迹和复制分析报告；
- 提供 45 个 MoonBit 自动化测试、严格检查脚本、持续集成配置和源码行数验收脚本。

## 技术实现说明

项目主体使用 MoonBit 实现，核心代码包含值类型与字段模型、边界候选域生成、笛卡尔路径枚举、规则执行、优先级决策、冲突检测、覆盖率统计、证据生成和版本行为差异分析等模块。项目当前包含 5,000 行以上手写源码，其中 MoonBit 是占比最高的单一编程语言；核心库可通过 MoonBit JavaScript 后端生成浏览器可加载的模块。

规则分析采用有界边界枚举方法。对于布尔值和枚举字段，系统使用全部合法值；对于整数字段，系统提取最小值、最大值、中点，以及每个规则阈值的前一个值、当前值和后一个值。在可配置的路径预算内组合这些候选值并执行全部规则，从而重点覆盖最容易出现边界错误的输入，同时避免直接遍历大范围整数带来的组合爆炸。

项目结构主要包括：

- `value.mbt`：值类型、比较运算和字段类型；
- `model.mbt`：规则、输入、输出、问题证据和分析报告模型；
- `domain.mbt`：边界候选域生成和路径枚举；
- `evaluator.mbt`：条件匹配、规则执行和优先级决策；
- `analyzer.mbt`：冲突、不可达、遮蔽、缺口和重复规则检测；
- `diff.mbt`：两个规则版本的行为差异分析；
- `fixtures.mbt`：电商、报销、内容访问和保险受理示例；
- `rulescope_wbtest.mbt`：MoonBit 自动化测试；
- `cmd/rulescope/`：命令行入口；
- `web/core/`：MoonBit JavaScript 外部库导出层；
- `dist/`：本地 Web 工作台；
- `docs/`：架构、申报和演示文档；
- `scripts/`：构建、测试和源码统计脚本。

## 原创性说明

本项目不是移植项目，也不是对现有规则引擎或开源项目的简单改写。moon-rulescope 的问题定义、边界候选生成方法、规则优先级语义、冲突分类、覆盖统计、反例结构、行为差异模型、命令行演示和本地网页界面均围绕“业务规则上线前的质量检查”这一具体需求独立设计和实现。

项目没有迁移第三方项目代码，也不依赖外部规则服务或在线大模型得出分析结论。与普通规则引擎主要负责执行规则不同，moon-rulescope 重点分析多条规则组合后的矛盾、遗漏和变化影响；与通用文本分析工具相比，项目输出具有确定性，同一个规则集和输入域会得到相同结果，适合加入自动化测试和持续集成流程。

后续计划继续增强以下能力：

- 增加 OR 条件、集合包含、字符串模式和日期区间等规则表达能力；
- 根据冲突反例自动生成 MoonBit 或 TypeScript 回归测试；
- 增加真实业务数据的本地离线回放和规则覆盖统计；
- 增加规则依赖图、增量分析和大型规则集性能优化；
- 在保持确定性核心的基础上，增加可选的自然语言转 DSL AI 适配器；
- 发布到 mooncakes.io，并持续完善文档、示例和社区集成。
